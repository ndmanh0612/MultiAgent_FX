# Backtesting & Performance Evaluation Methodology

## 1. Overview

The evaluation module ([`app/evaluation/backtester.py`](file:///app/evaluation/backtester.py)) provides a rigorous, bias-free quantitative backtesting harness for signals generated by the **Forex AI Multi-Agent TradingAgents Pipeline**.

It guarantees:
- **Zero Look-Ahead Bias**: Every signal is evaluated strictly against future out-of-sample candles occurring after the decision candle close.
- **Realistic Transaction Costs**: Simulates broker spread and execution slippage on every trade.
- **Conservative Intrabar Resolution**: Handles ambiguous candle spikes without optimistic bias.
- **Benchmark Comparison**: Evaluates agent performance against an algorithmic EMA20/EMA50 trend crossover baseline.

---

## 2. Core Evaluation Principles

### 2.1 Conservative Intrabar Resolution
A notorious flaw in algorithmic backtesting is the **intrabar conflict problem**: during an H1 bar with extreme volatility, the candle's High may reach the Take Profit (TP) while the Low breaches the Stop Loss (SL). 

Naive backtesters assume TP was reached first, artificially inflating the win rate. 

**Our Solution:**
```python
# app/evaluation/backtester.py
if reaches_tp and reaches_sl:
    # CONSERVATIVE RULE: Always assume Stop Loss was hit first
    return TradeOutcome(outcome="LOSS_SL", exit_price=signal.stop_loss, ...)
```
By prioritizing SL over TP whenever ambiguous intrabar spikes occur, our backtesting results represent a conservative lower bound of expected performance.

---

### 2.2 Realistic Frictional Costs
For every trade:
1. **Spread Deduction**: Subtracted from the gross pip move based on historical market snapshot spreads.
2. **Slippage Buffer**: Default `0.2` pips applied against the entry and exit prices.

## 3. Quantitative Metrics

The evaluation module calculates standard institutional performance metrics:

| Metric | Formula / Description | Importance |
| :--- | :--- | :--- |
| **Win Rate (%)** | `(Winning Trades / Total Closed Trades) * 100` | Basic success frequency. |
| **Total Net Pips** | `Sum(PnL in Pips)` across all trades | Aggregate edge after transaction costs. |
| **Profit Factor** | `Gross Profits / Abs(Gross Losses)` | Ratio of gross profits to gross losses (> 1.5 target). |
| **Expectancy (Pips)** | `(Win% * Avg Win Pips) - (Loss% * Avg Loss Pips)` | Expected return per signal executed. |
| **Max Drawdown (Pips)** | Peak-to-trough decline in cumulative pips | Maximum historical capital risk. |
| **Average Bars Held** | `Mean(bars between Entry and Exit)` | Duration of capital exposure. |

## 4. Algorithmic Baseline Comparison

To verify that the Multi-Agent LLM reasoning adds actual alpha, the backtester executes an identical backtest using an **EMA20 / EMA50 Trend Following Baseline**:
- **BUY Condition**: Fast EMA20 crosses above Slow EMA50.
- **SELL Condition**: Fast EMA20 crosses below Slow EMA50.
- **Exit Condition**: Inverse EMA crossover or trailing stop.

Multi-Agent LLM signals must demonstrably outperform this baseline in **Expectancy** and **Profit Factor** to justify LLM compute costs.
